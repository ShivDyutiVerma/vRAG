## Surprises & learnings

- "The endpoint hangs" and "the endpoint works but our specific request triggers a provider bug"
  can look identical from the outside (both present as timeouts) until you vary one thing at a
  time against a now-healthy API. Worth re-testing the exact failing request in isolation the
  moment a "the whole thing is down" theory becomes falsifiable, rather than assuming the original
  diagnosis (P-R13, outage) explains everything that comes after it recovers.
- A reasoning model with structured output mode is a genuinely different beast from a plain chat
  model: the reasoning trace is billed against the same token budget as the actual answer, so
  "give it more max_tokens" and "turn off reasoning" are two different levers that both matter,
  and getting only one right (as the first fix attempt did) still fails.
- Catching the model answering in the wrong language via G4's overlap score dropping, rather than
  via a dedicated language check, is a nice accidental validation that G4's mechanism (even
  uncalibrated) does real work — it correctly rejected an ungrounded-in-the-relevant-sense answer
  for a reason the guardrail's author hadn't specifically anticipated.
- Non-streaming "structured JSON from an LLM" and "low latency" are close to opposites when the
  model does any internal reasoning or the schema is non-trivial — worth remembering for any
  future stage design that both wants structure and wants speed: they may need to be earned
  separately (schema constraints for the first, real streaming for the second), not assumed to
  come together for free.
