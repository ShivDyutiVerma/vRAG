## Surprises & learnings

- `retrieve()`'s "never raises" contract has a real consequence for retry design: a retry policy
  can only do something if the wrapped call can actually fail loudly. Wrapping a
  never-raises function in tenacity is a checkbox that looks like hardening but does nothing —
  worth testing the *mechanism* in isolation and being honest about what it's not attached to yet,
  rather than wiring it somewhere it can't matter just to say "retries: done."
- Guardrails changing a response's status can break an existing test in a way that's actually a
  *correction*, not a regression — the old empty-query test expected `abstained`, but `abstained`
  should mean "valid query, nothing relevant found," not "degenerate query." Worth pausing on a
  failing test to ask which side is wrong before just editing the test to match new behavior.
- Two people pushing to `main` directly (rather than strictly via the PR flow the docs describe)
  still worked out fine here because the module ownership split held — R's commits only touched
  R's files (plus one trivial lint-equivalent touch of two P files), so there was nothing to
  actually reconcile at merge time. The ownership boundary is doing more of the conflict-avoidance
  work than the branch/PR ceremony is.
