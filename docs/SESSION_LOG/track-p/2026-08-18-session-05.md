## Surprises & learnings

- A calibration sweep can hand back a real, uncomfortable finding instead of a clean number: R's
  data didn't just fill in a placeholder, it proved the original spec's two targets are
  incompatible on this corpus. The right response wasn't to quietly pick whichever point looked
  best — it was to make the tradeoff visible (with real reference points, not vague options) and
  let the person who owns the product call take the call, exactly because "how often should this
  refuse a real question" has no data-only right answer.
- A guardrail whose threshold was set against the wrong assumed scale can be *worse* than useless
  in a subtle way: not "always refuses" (loud, obviously broken) but "never fires at all" (silent,
  looks like it's working because the pipeline runs fine, but the check is doing nothing). Worth
  checking a guardrail's actual real-world hit rate, not just that its code path executes.
- The most useful thing about building the circuit breaker wasn't the state machine itself
  (closed/open/half-open is standard, well-understood) — it was noticing that "count every
  failure" is the wrong default when the system already has an intentional, expected way to fail
  fast under budget pressure (the two-track design). A circuit breaker needs its own definition of
  "failure" tailored to what the calling code already treats as normal, or it just duplicates (or
  actively fights) a mechanism that's already there.
