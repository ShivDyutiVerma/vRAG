## Surprises & learnings

- A negative result from a live probe ("tools + strict JSON doesn't combine reliably") was just as
  valuable as a positive one here — it directly shaped the architecture (two-phase escalation
  instead of one combined request) before any implementation code was written, avoiding a design
  that would have looked reasonable on paper but failed against the real API.
- The most consequential finding of the day came from trying to verify a feature works, not from
  building the feature itself. The instinct to actually run the full live chain (rather than
  stopping at "the mocks pass, the mechanism is sound") surfaced a correlation about Sarvam's
  reliability that the earlier, less-targeted P-017 testing hadn't revealed — insufficient-context
  answers specifically, not a random subset. Worth remembering: a feature's mocked tests proving
  the *logic* is correct is a different claim from the *live dependency* cooperating, and the gap
  between them can itself be the most useful thing learned from doing the work.
- Isolating whether a bug predates a change (by reproducing it against the old code path, not just
  the new one) turned an ambiguous "did I just break this?" moment into a confident "no, this was
  already true" finding in a few extra minutes — cheap insurance against chasing a phantom
  regression, and it made the sharper P-R20 characterization defensible rather than just plausible.
